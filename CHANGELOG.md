# Changelog

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and
this project follows [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Because the repository is the companion code of a published paper, any release
that changes the values in `results/` is a major release, and the change is
recorded here explicitly.

## [1.0.0] - 2026-09-17

Initial public release, accompanying *Bridging the Connectivity Gap: A
Crowdsourced Software Architecture for Multimodal Public and Para-Transit
Integration* (ICEEET 2026).

### Added

- Capability-flag model of eight functional-requirement aspects (FR1-FR8), with
  Existing and Proposed as two named settings of the same flags.
- Trip aggregation engine: multi-criteria Connection Scan over a timetable, with
  a Pareto front over arrival time, transfers and fare, and three ranking
  criteria (FR1, FR2, FR3, FR7).
- Real-time information engine: an official feed plus a three-layer
  crowdsourcing pipeline of plausibility filtering, credibility scoring and
  consensus formation (FR4, FR5).
- Para-transit engine: Poisson driver arrival with naive hailing and coordinated
  dispatch (FR6, FR8).
- Synthetic network generator: 40 stops and 10 routes over a 35 x 25 km service
  area, uniform or clustered stop placement.
- Isolated single-factor ablation and fully stacked Existing versus Proposed
  comparison, both over one shared set of stochastic inputs.
- Robustness layer: `SimulationParameters` holding every varyable constant and
  the six seeds, and `RobustnessService` providing a repeated-seed analysis and
  ten one-at-a-time sensitivity sweeps over 43 levels.
- REST API under `/api/comparison` with 14 JSON endpoints, and a Chart.js
  dashboard at the application root.
- Read-only CSV views of the stacked comparison, the ablation, the repeated-seed
  analysis and the sensitivity sweeps, under `/api/comparison/csv/`.
- Committed result files under `results/`, regenerated by fetching the `/csv/…`
  endpoints, so the numbers can be inspected without running the simulation.
- `docs/REPRODUCING.md`, mapping each paper table and figure to the command,
  output file and columns that produce it.
- JUnit 5 test suite (48 tests, about 25 s): snapshot tests locking the stacked
  comparison and the ablation rows to within 1e-9, determinism tests over the
  seeds, reflective checks on the `SimulationParameters` copy methods, shape
  checks on the robustness analyses, and a Spring Boot slice test covering every
  endpoint.
- GitHub Actions workflow checking the determinism contract on every push and
  pull request.

### Determinism

With the default seeds, `GET /api/comparison/stacked` reports an
itinerary-found rate of 46.0 % for Existing and 96.66666666666667 % for
Proposed. Builds are reproducible: `project.build.outputTimestamp` is fixed, so
two clean builds of the same source produce byte-identical artifacts.
